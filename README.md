# ☁️ Cloud Architecture & Security

## 📌 Project Overview

This project focused on reviewing cloud architecture and security requirements for enterprise applications and technology services.

I worked with cloud architects, cybersecurity specialists, infrastructure teams and application owners to understand the proposed cloud setup, discuss design choices and identify areas where security or architecture improvements were needed.

My role combined technical project management with active involvement in cloud architecture, IAM, network security, data protection and technology risk discussions.

---

## 🎯 Business Challenge

Cloud adoption introduced a different set of architecture and security questions compared with traditional infrastructure.

The main challenge was to make sure that cloud solutions were designed in a way that was technically sound, secure and suitable for an enterprise environment.

Key topics included:

- Identity and access management
- Network architecture and connectivity
- Data protection and encryption
- Logging and security monitoring
- Responsibilities between the company and the cloud provider

## 🏗️ Cloud Architecture Approach

We reviewed the cloud solution as an integrated architecture rather than looking at individual cloud services in isolation.

```text
Business Application
        │
        ▼
   Cloud Workload
        │
 ┌──────┼──────┐
 ▼      ▼      ▼
IAM   Network  Data
        │
        ▼
Security Controls
        │
        ▼
Logging & Monitoring
        │
        ▼
Cloud Provider Services
```

The discussions focused on how the different components worked together and where dependencies or security gaps could emerge.

Typical questions included:

- How are users and service accounts authenticated?
- Which identities have privileged access?
- How is network access restricted?
- Which data is stored or processed in the cloud?
- Which security responsibilities remain with the customer?

---

## 🔐 Identity & Access Management

IAM was one of the key areas because cloud environments rely heavily on identities, permissions and service accounts.

Together with the relevant SMEs, I reviewed topics such as:

- Role-based access
- Privileged access
- Service accounts
- Authentication requirements
- Separation of duties

The goal was to make sure that access rights matched the actual business and technical requirements and that unnecessary privileges were avoided.

---

## 🌐 Network & Data Security

Another focus area was the way cloud workloads communicated with internal systems, users and external services.

We discussed:

- Network segmentation
- Private and public connectivity
- Firewall and access rules
- Data encryption
- Data location and handling

I worked with infrastructure and security specialists to understand how these controls were designed and where additional safeguards were required.

---

## ⚠️ Cloud Risk & Shared Responsibility

A recurring topic was the shared responsibility model.

Not every security control is handled by the cloud provider. Depending on the service model, important responsibilities remain with the customer.

We therefore looked at questions such as:

- Which security controls are managed by the provider?
- Which controls must be configured by the customer?
- Who owns IAM and access reviews?
- Who is responsible for logging and monitoring?
- Which risks depend on configuration decisions?

This helped clarify ownership and avoid assumptions that cloud services were automatically secure by default.
